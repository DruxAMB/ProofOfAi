The problem

A creator posts work; weeks later a dispute over who made it first can't be settled by file metadata — it can be edited freely. A public timestamp anchored to a wallet settles it, but only if the timestamp can't be forged and the content never has to be uploaded anywhere.

What ProofOfAI is

Browser-side hashing. keccak256 runs client-side — the file never leaves the machine. Only the 32-byte digest touches the chain; privacy by construction.
Anyone can verify. Paste a hash; get back exists, author, timestamp, kind — a free read call, no wallet needed.
One content, one record. Re-notarizing an identical hash reverts (already notarized) — duplicates can't rewrite history.
Permanently addressed. UUPS + ERC1967 proxy: the implementation can be upgraded while the address consumers verify against never changes.

Why it fits BOT Chain

  • Native utility, not a wrapper — provenance is infrastructure every AI-content tool on the chain can call without permission.
  • Real transaction surface — every attestation is a user-paid mainnet transaction with a durable on-chain artifact.
  • Privacy-preserving by design — hash-only storage proves existence without exposing content; no custodial upload anywhere.
  • Composable — any contract can call verify on-chain; tipping, badges and oracle consumers can gate on attestation.

Roadmap

  • Attestation feed UI (recent notarizations) beyond hash-only lookup.
  • Batch notarization — one tx, many hashes, for publishing pipelines.
  • Signed-metadata attestations linking hashes to AgentID registry entries.
  • Verify-as-middleware snippets other BOT Chain dApps can drop in.
